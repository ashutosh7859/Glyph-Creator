# Architecture decisions

## Current system

The project is a local Windows desktop application with three distinct
responsibilities:

1. `CadTextCreator.App` is the WinForms presentation layer. It accepts a
   single line of text and layout settings, previews composed geometry, and
   starts DXF export.
2. `CadTextCreator.Core` is a .NET 8 library with no AutoCAD references. It
   loads the glyph repository, resolves an exact face and Unicode scalar,
   composes and validates contours, and writes DXF.
3. `build_font_library.py` is an offline authoring tool. FontTools extracts
   outlines, resolves composites through the font glyph set, flattens curves,
   calculates metrics, assigns containment depth, and writes repository JSON.
   Normal UI use does not need Python or a font file.

`font-library.json` is the versioned canonical runtime repository for the
initial implementation. It records exact face identity and version, source
asset filename and SHA-256, license notice, units-per-em, curve tolerance,
per-codepoint metrics, contours, closure, role, nesting depth, and ignored
zero-area contour count. The repository is JSON so the runtime needs no
database/provider package and files remain inspectable as fixtures. A database
is not justified by the current library size.

DXF is generated by the C# core without Autodesk APIs. Each contour is one
closed `LWPOLYLINE` on `TEXT_OUTLINES`. `$INSUNITS` is unitless (`0`); the
requested text height and insertion coordinates are expressed in the
drawings' units. AutoCAD/Civil 3D is an optional downstream consumer, not a
runtime dependency.

## Decisions

### C# owns runtime composition

The revised design makes text layout and output orchestration reusable from
the application, not from an AutoCAD transaction or a Python process. C# is
the runtime owner; font extraction remains an offline Python utility because
the existing FontTools prototype already contains usable curve handling.
The C# runtime never loads TTF/OTF files and never asks AutoCAD to outline
text.

### Retrieve pre-generated geometry

Extracting once and validating the stored records keeps normal composition
deterministic and independent of installed fonts. Each face is selected by an
exact ID and each glyph by a Unicode scalar. The application does not
substitute faces or silently drop missing glyphs. JSON is the current
canonical format; SQLite can be reconsidered only if repository scale or
concurrent authoring demonstrates a need.

### WinForms desktop UI

Repository audit found no UI in the existing Glyph Creator project. The
separate Civil 3D plug-in has WinForms and WPF references but is coupled to
Autodesk APIs and is not reused. WinForms was selected for the initial
Windows-only UI because it fits the target CAD user's Windows environment
and avoids adding a separate cross-platform UI framework. The backend remains
portable and independently buildable. The UI itself cannot be executed in
the current Linux validation environment.

### AutoCAD remains optional

The former CAD-command-first plan is superseded. The app creates an
independent DXF file; import/REGION/SOLID behavior must be validated in an
actual target host separately. The `PolylineSolids` project remains a
separate Civil 3D tool and is not a dependency.

## Scope and limits

- The bundled face is DejaVu Sans Book with printable ASCII (U+0020–U+007E).
- Composition is a simple left-to-right Unicode-scalar sequence. Advanced
  shaping, kerning, bidirectional and complex-script layout, multiline text,
  and universal Unicode are unsupported.
- Text height scales the face's units-per-em to the requested drawing-unit
  height. Width factor scales horizontal geometry and advance; tracking is
  an additional drawing-unit gap between successive glyphs (negative values
  tighten spacing); rotation is
  counter-clockwise around the baseline insertion origin.
- Degenerate point/zero-area contours are excluded during ingestion and
  counted on their glyph record. Non-degenerate contours must be finite,
  closed, simple polygons. Hole/outer role comes from containment depth, not
  winding direction.
- DXF parser checks are not AutoCAD/Civil 3D host checks.

## Existing-component migration

| Component | Decision |
|---|---|
| `glyph_creator.py`, `glyphs.json` | Retain as a separate open-stroke utility; do not feed it to the outline runtime. |
| `font_outline_creator.py` | Reuse its outline pen for offline ingestion; retain its standalone DXF CLI. |
| `extract_text_details.lsp` | Retain as an independent CAD diagnostic. |
| `text_to_dxf/` | Leave as a separate Python prototype/reference; do not add a service or dependency. |
| `PolylineSolids/` | Leave as a separate Civil 3D plugin; no command integration required. |
